The season step is not shown at all. Episodes are added straight to the series, in file order.

Why this matters Today the operator has to know this rule and encode it themselves — a season number in a flat series is an error, a missing one in a seasons series is another. Those two error messages account for a large share of failed uploads. In the new flow the rule is enforced by the interface, so neither mistake is possible.

Scope

What This Phase Delivers

Nothing is removed from the platform. Two things move to screens that already exist, and one returns in a later phase.

✓ Included now

  • Series and season selection by dropdown, with search
  • Season step shown only where it applies
  • Single-file episode upload, two required columns
  • Review screen with per-row warnings before anything saves
  • Row selection — add 23 of 24 if preferred
  • Inline create season so the page never has to be left
  • New template file and a one-page guide

→ Moves or comes later

  • Creating series in bulk — done on the existing Series screen, one at a time
  • Creating seasons in bulk — done on the Series screen, or inline here
  • Editing existing episodes by file — a later phase, see below
  • Multiple seasons per upload — one season per upload for now
Why editing by spreadsheet comes later Episodes can be reordered by dragging them in the CMS, which renumbers them. A spreadsheet that identifies episodes by number could therefore update the wrong one after a reorder — silently. When this returns, it will work by downloading the current episode list and editing that file, so every row carries a permanent identifier. Leaving it out of the first release keeps this delivery simple and safe.
Unchanged The same roles keep access — Owner, Content Admin and Content Manager. Media files are read from the same storage in the same formats. The Series, Videos and Audio screens are untouched, and existing content is unaffected.
Sign-off

Four Decisions Needed

Each carries our recommendation. Confirm these and development can begin.

1

Is creating series one at a time acceptable?

New series are added far less often than episodes. Recommendation: yes — create them on the existing Series screen and keep bulk upload focused on episodes.

2

Is one season per upload acceptable?

Three seasons would mean three uploads. Recommendation: yes — it keeps the flow unambiguous, and each upload takes seconds to set up.

3

Should the automatic series trailer be kept?

Today a newly imported series automatically gets a short trailer taken from its first episode. Recommendation: keep it — applied when a series has no trailer yet and episodes are uploaded to it.

4

Should the current three-file import stay available during changeover?

It could run alongside the new flow for a period. Recommendation: no — running both invites confusion, and the new flow covers everything the content team does today.

Next step On approval of these four points, development begins. No change reaches the live platform until the new flow has been tested end to end with a real batch of episodes and walked through with the content team.
